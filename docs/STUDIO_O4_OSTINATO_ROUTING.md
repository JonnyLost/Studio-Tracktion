# O4 — Arrangement routing and melodic modes

Base: O3 4d3913ab5ef866681119f811e728cf92fdd30505. O1/O2 standalone Linux and Intel Mac CI passed; O3 full native CI still running at inspection. No merge into the Universal Instrument System.

## Workflow
Open Navigate > Ostinato Engine in a project with initialized instruments. Assign rows to existing tracks and MIDI channels. Fixed pitch repeats the row note; Root + intervals uses the row MIDI note as the root and signed semitone offsets per step. Apply the row and step edits before audition. For example, root 60 and offsets 0, 7, 12, 7 produce C4, G4, C5, G4. Multiple rows may use the same track, including mixed rhythmic divisions. An enabled out-of-range pitch is refused, not silently wrapped or clipped. Existing O1/O2 files migrate to schema 3 with fixed pitches and zero intervals.

Stop the arrangement transport, choose 1–256 master repeats (maximum ten minutes), then click Audition. It sends generated note-on/off messages through existing instrument tracks, not an additional instrument or audio engine. It respects row mute/solo and existing track processing. No clip creation, take recording or project playhead movement occurs. Stop, close the window, start normal playback/recording or switch projects to end audition. Mixer, Effects and Stage shortcuts stop audition before navigating. Pattern edits are disabled during the run. No simultaneous manual MIDI input on audition destinations: the existing MIDI path cannot distinguish overlapping same-channel/pitch notes from hardware or other audition tools. Release held manual notes before starting; do not play them during the run.

## Timing and guards
OstinatoAudition.h prepares finite absolute event deadlines from the tempo map at the current arrangement position and dispatches via a JUCE message-thread timer requesting 5 ms intervals. This is best-effort audition, not sample-accurate playback or a transport-synchronized audio-thread sequencer. Tempo-map changes, playhead changes, normal playback/recording, pending plug-in loads, project or route invalidation stop the run. Each route binds to the existing track ID and instrument instance ID; initialized hosted plug-ins are required. No fallback routing. Note-offs are sent only to original still-valid destinations; if the instrument or audio context is destroyed, cleanup relies on the host graph teardown. A callback over 100 ms late aborts and releases held notes instead of bursting overdue events. Dispatch is bounded to 512 events per callback. The core normalizes generated duplicate hits, but external note ownership and arbitrary MIDI processors are outside its guarantees.

## Verification and limits
Added schema migration, interval rendering, range validation, absolute-deadline dispatch and stop/stall tests to the standalone suite and a melodic editing check to native interface review. Full native CI and standalone sanitizer workflows cover O4. Native compilation and physical audition are not yet verified in this session. No claim of live transport sync, keyboard-root following, chord detection, simultaneous arrangement playback, audio-thread scheduling, CC1/CC11 control or MIDI printing. Those require subsequent milestones; O5 will establish the controller ownership and conducting architecture. The user should test existing ARIA, native synth and sampler routes on the Mac before relying on audition.

# P3 — Studio Spatial native effect

Base: P2, whose standalone Linux/Intel macOS DSP checks passed. No merge. P3 adds the actual native Tracktion insert and floating editor to Studio. The source processor is not an AU/VST, and it needs no Panagement installation. Stable type studioSpatialSourceV1, settings key studioSpatialSourceSettingsV1.

## Use
Stop playback, select a regular audio or instrument track, open its channel insert menu and choose Add Effect > Studio Spatial. The insert is placed before the track volume/fader and its editor opens. Reopen from the existing insert menu. Use an ordinary new test project or a copy of an existing one, not the only copy of a production project. Do not install on the legacy Room Return. Existing Stage pan, legacy room send and shared room remain unchanged. For isolated listening tests leave Stage routing disabled, use center mixer pan and turn off other spatial plugins; combining independent panners can create unintended coloration. No automatic routing or migration. P3 supports stereo track insert, not group/master/surround or clip/rack processing. Mono sources should arrive in the stereo Tracktion path; if host supplies fewer than two channels the adapter leaves it unchanged.

The floating window uses Studio's current theme and shared font scale. Drag the rectangular position pad for left/right direction and close/far perceptual distance; the sliders provide keyboard-accessible alternatives and exact numerical entries. Distance is not metres. Controls: direction +/-90 degrees, distance -100..100%, width 0..200%, tilt +/-6 dB, air damping/distance width 0..100%, independent ear timing/level/head shadow 0..200%, focus 0..100%, amount 0..100%, gain -24..+12 dB, mono check. Eight original factory presets (Neutral, Near solo, Left ensemble, Right ensemble, Middle distance, Distant ensemble, Wide stereo, Speaker-friendly position). Presets and Reset apply all settings in one transaction; custom settings persist per insert in the project. No user preset file library, host automation lanes or docked inspector editor yet. Output peak readouts are not a correlation or loudness meter. Amount zero preserves dry signal except independent output/mono controls; use the Bypass toggle for true Tracktion insert disable, retaining all settings. All neutral defaults preserve ordinary stereo input. A floating editor re-resolves its original track/plugin IDs and generation; deleted or unavailable instance disables controls rather than retaining stale pointers. Project change destroys the editor. Theme and text scale changes refresh it; compact-display and largest-text acceptance still required.

## State and realtime contract
Versioned, bounded 13-scalar string serialized with classic locale and round-trip precision; malformed/nonfinite/unknown-version settings fall back to neutral, valid scalars clamped. One undoable property per complete snapshot, undo/redo and reload via Tracktion state. Constructor publishes state; message-thread ValueTree listener publishes validated atomic float array using even/odd revision and one writer. Reader bounded to one snapshot attempt; if publication overlaps keep last coherent plan. No audio-thread state access, string parsing, mutex or allocation. Rate-specific coefficient math is calculated on the processing owner during initialise or once when a new coherent snapshot arrives at a block boundary (not per sample). This is a deliberate limited deviation from P1/P2's off-thread plan generation contract, to prevent stale-rate plans during device changes; measure its cost under rapid automation before extending automation. DSP smooths controls across samples. No fixed lookahead latency, intentional far-ear delay. Handles context offset/count bounds and preserves unexpected extra channels. Two atomics publish output peaks with approximate block-dependent decay. Existing Tracktion lifecycle serializes initialise/deinitialise/render; no independent background worker. No claim of complete real-time performance until native testing.

# Studio Sampler

## Play an instrument

1. Open **Instruments**, select **Studio Sampler**, and choose **Add as New Track** or **Load on Selected Track**. The editor opens in **Basic**. Reopen it from **Channel → Open Instrument** or from Instruments with the sampler track selected.
2. Drop a WAV or AIFF on the waveform or choose **Load Sample**. The first sample maps across the keyboard with root C4. Play the onscreen keys, assign a MIDI input from Channel, or create a MIDI clip and audition a note in the Piano Roll.
3. Shape the sound with Attack, Decay, Sustain, Release, Volume, and Tune. **Audition** plays the selected sample at its root, using the instrument's current amplitude settings and the zone's playback mode. Click again to stop it.
4. In **Mapping**, add samples, select a zone in the menu or plot, and set its root, key and velocity limits. Drag the left and right edges of a zone to change its key range. The vertical axis represents MIDI velocity from 1 to 127. Middle C is C4 (MIDI 60), as it is in Studio's Piano Roll and MIDI Monitor.
5. In **Loops**, enable the loop for a sustained zone, then drag the markers or enter the positions in source frames. The end frame is exclusive. **One-shot** runs the sample to its end after a note-off. **Advanced** sets maximum voices, pitch-bend range and the selected zone's round-robin group.
6. Choose **Save Preset** to reuse the instrument. Use Studio's project **Save** to keep the current instrument and clip settings, including edits made since the last preset save. If a media file is unavailable after reopening, select its zone and choose **Locate Sample**.

## Architecture

Milestone 5 starts from Milestone 4.5 commit `62603a194f313c3d344343574caf9e7ef82359c9`. Studio registers a Tracktion built-in instrument with the type `studioNativeSampler`. Browser insertion follows the same compatibility and placement rules as a hosted instrument. Tracktion owns the clip, input, plug-in graph, and project lifecycle. The sampler adds stereo audio at the instrument position ahead of inserts and the track fader. The same track supplies metering, pan, mute, solo, Master routing, and the existing Stage balance and post-fader room send.

The pinned Tracktion sampler takes a render-time lock and creates and destroys voice objects while rendering. Its simple sample mapping would also require separate channel expression, velocity and envelope behavior. Studio owns a C++20 voice engine and uses JUCE for WAV/AIFF decoding, window controls, and state I/O. The Swift prototype used an Apple sampler unit per track and routed previews through that track's mixer. Studio carries forward the track-owned signal and preview routing. [Swift PlaybackEngine](https://github.com/JonnyLost/Garritan-studio/blob/main/DAWCore/Sources/DAWCore/Audio/PlaybackEngine.swift)

The renderer uses fixed-size voice, controller and round-robin storage. It linearly interpolates source samples with fractional positions based on source and output sample rates, note, tuning and bend. Short end fades and loop-seam blends reduce discontinuities. The oldest voice in release is stolen first, then the oldest sounding voice. Overlapping group-zero zones layer in instrument order. Each nonzero group plays one matching, loaded zone in order per strike and advances its own cursor. Overlapping groups can play together. A group number is local to an instrument. Changing the loaded sample set clears its voices and restarts round robin.

MIDI retains its original channels. Incoming channels each have their own sustain, channel volume, expression, pressure, modulation, and pitch bend. CC1 and channel pressure each increase 5 Hz pitch vibrato to at most half a semitone. The greater of the two controller values supplies depth. Polyphonic aftertouch has no sampler destination. Tracktion still uses its configured channel for ordinary single-channel MIDI clips. Preview events use neutral controller state and remain outside the recording stream. The waveform button, editor keyboard, and Piano Roll have separate preview identities. Stop and Tracktion's playback discontinuity flag clear active voices and reset sampler controllers.

The model opens and validates files on the message thread and publishes immutable banks. The render callback borrows a bank for one block without locking, allocating or decrementing sample reference counts. The publisher reclaims retired banks on the message thread. Render events are bounded to 4,096 incoming MIDI events per block, with voice cleanup on overflow. An overflow in the separate 128-event preview queue clears preview voices. The working limits are 64 voices, 128 zones, 64 MiB decoded per source, and 256 MiB of decoded audio per instrument. Repeated paths share PCM within an instrument. Preparing a different preset can temporarily retain both sets of PCM, and the render callback may still hold an earlier bank until the block finishes. Larger imports and preset loads may briefly pause the editor. Resource Inspector reports active and maximum voices, unique loaded samples, and decoded PCM memory.

## State and sample references

Both the `.studiosampler` document and Tracktion's `studioSamplerState` plug-in property store XML with a `STUDIO_SAMPLER` root and a `version` attribute. Version 1 records instrument and preset names, the envelope, gain, tuning, voice limit, bend range, and each zone's source, key/velocity ranges, loop, playback mode, gain, tuning, and group. A preset save uses a temporary file and an atomic replacement. The file contains references to the media files.

Presets store relative references for media below their directory and absolute references for other media. Project state records the absolute source and a project-relative path for sources below the project directory. On reopen, the original path takes priority so a Save As in a directory with similarly named media retains the source. If the original path is unavailable, Studio tries the recorded relative path. Keep related presets and samples in the same folder hierarchy when relocating them. A missing file leaves its zone and settings intact. Relinking retains the mapping. A replacement that is too short for an enabled loop prompts the user to adjust or disable that loop first.

## Verification

The standalone sampler tests render synthetic audio and check MIDI amplitude and channel behavior, sample-rate conversion, frequency ratios, ADSR, stealing, key and velocity limits, overlap, round robin, loops and one-shot playback. The Studio integration test uses generated 24-bit WAV and AIFF and a Tracktion hosted device to test sample import, editor interactions, preview, stop and seek, channel-3 MIDI recording and CC retention, clip playback, Room Return routing, presets, project reopen, and sample relinking. The keyboard test sends mouse events when the native window is available for hit-testing and uses JUCE keyboard state to check note dispatch when the runner hides its windows. The Intel workflow runs these tests with the existing MIDI, spatial, acoustic, hosted routing, and interface suites. The `Studio-M5-sampler-review` artifact contains the four native JUCE editor captures from the macOS runner.

On a physical Intel MacBook, check the complete load-and-play workflow with a Core MIDI keyboard, including recording notes and CC changes and replaying the take. Check audio device changes, round-trip latency, CPU and dropouts at 64 voices, and project reopening with the real ARIA Audio Unit installed. At 1024 × 640 and 1280 × 800, verify actual file dragging, keyboard focus, load and save dialogs, and trackpad resizing with the Studio appearance settings. For ARIA, follow the existing [restoration procedure](../RESTORATION_TEST.md).

Advanced formats, disk streaming, velocity crossfades, legato, release triggers, articulation and microphone layers, advanced modulation, and the alternate synthesis engines remain future work.

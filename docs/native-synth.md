# Studio Synth

## Baseline and recovery

The Tracktion application is in [JonnyLost/Studio-Tracktion](https://github.com/JonnyLost/Studio-Tracktion). This branch starts at `f60dd903e46e3958ffd96862e77fbcfdb29b1f15` on `feature/studio-native-sampler-m5`. That commit is Studio 0.2 and already contains the native sampler. Tracktion Engine is pinned to `c6293127cdc0a8488aea2ae0907f4709ee89c228`. The welcome-screen branch and Milestone 5 share the Milestone 4.5 base. Any subsequent welcome-screen integration should reconcile both branches' edits to `Studio.cpp` and `CMakeLists.txt`.

The historical source is [Garritan-studio’s factory validation revision](https://github.com/JonnyLost/Garritan-studio/tree/3787b60263b0f8d0188f82e626d12c40d17dc86f). Only the original host-independent DSP sources, their headers and test harnesses were copied. The original package includes its physical-model refinements. The original catalog was executed using its Foundation-only Swift patch types and recipe constructors. Its export preserves catalog IDs, categories, parameter values, layer configuration and modulation. Internal UUIDs generated by the factory constructors are regenerated deterministically and their layer references are remapped together.

| Family | Recovered DSP | Host adaptation |
| --- | --- | --- |
| Analog | StudioAnalogDSP oscillators, amp and filter envelopes, original node routing and patch graph | Tracktion event timing replaces the historical standalone sequencer. Optional saved cable graphs are compiled before publication. |
| FM | StudioFMDSP four operators, four algorithms, feedback, envelopes and velocity brightness | The adapter supplies graph input and per-track output. |
| Wavetable | StudioWavetableDSP original mipmapped tables, custom spectrum and morphing | Static table construction stays in the native preparation phase. |
| Additive | StudioAdditiveDSP sixteen partials, envelopes and motion | The original parameter IDs drive editor controls and normalized modulation. |
| Granular | StudioGranularDSP procedural sources and StudioSharedPCM | JUCE decodes external files. Independent instances of the same recording share immutable PCM. |
| Physical Modeling | StudioPhysicalDSP eight models, pluck, bow, reed, brass and tuned resonances | MIDI and output are supplied by Tracktion. Acoustic realism requires listening tests. |
| Hybrid | Original layer and route recipes | A C++ coordinator mixes up to four native DSP instances into the same Tracktion instrument. Disabled layers allocate no engine instance. |

Swift AVAudioSourceNode wrappers, AVAudioFile decoding, the mixer nodes and the standalone Swift modulation timer were replaced by the Tracktion plug-in and a bounded render-time control plan. The original SwiftUI application shell has no entry point in the Tracktion host. The editor is a native JUCE component in its existing plug-in window, with a single project-backed patch. Swift is needed only if regenerating the factory data.

## Play and edit

Open the track creation menu and choose **Add Synth**, or select a family under **Instruments → Synth**. Browse factory sounds by family and category, or search by name. Select a preset, play from the displayed keyboard or choose a MIDI input, then use **Sound** for the family's main controls. **Shape** exposes its contour and expression controls. **Advanced** exposes the remaining historical engine parameters, the MIDI receive channel, per-layer mono or polyphonic voice limits, and layer management. Hybrid patches also show the layer controls on Sound. Select a layer to edit its engine, preset, gain, pan or enabled state.

Use **Modulation** to select an existing route, change its depth, or add a source and destination for the selected layer. Macro and LFO motion update the audio engine through the patch. Tracktion can automate **Synth Trim** and **Synth Macro Offset**. They affect runtime output separately from the preset's saved volume and macro.

**Save Preset** writes a named `.studiosynth` file. Choose a new filename to make a copy. **Load Preset** imports or reopens it, and **Advanced** offers **Show File** or confirmed deletion when a user file is selected. Factory sounds are immutable and editing them creates an edited project patch. Save the Studio project to keep that patch with the arrangement, automation and routing. Granular recordings remain external. The editor identifies a missing path and offers **Locate Audio**, while the affected layer stays silent until relinked. The import window uses at most 524,288 frames per recording, with no disk streaming.

Live and clip MIDI retain their incoming status channel. Receive defaults to Omni and can be set to one channel per instrument. Offsets divide the render block so MIDI changes take effect at their supplied frame. CC1 uses the native engine's destination. Pressure can raise that channel's CC1 value. Physical voices use native per-channel CC11. The other engines apply CC11 at the layer output using the receiving channel, or the average of held channels in Omni. The project persists imported MIDI Learn mappings. Preview uses the configured receive channel and stays outside the recorded MIDI stream.

## Build and test

Use Xcode and CMake on Intel macOS 14+. In a Tracktion checkout on the Milestone 6 branch, prepare the pinned dependency and build.

```bash
git init build/deps/tracktion-engine
git -C build/deps/tracktion-engine fetch --depth 1 https://github.com/Tracktion/tracktion_engine.git c6293127cdc0a8488aea2ae0907f4709ee89c228
git -C build/deps/tracktion-engine checkout --detach FETCH_HEAD
git -C build/deps/tracktion-engine -c url.https://github.com/.insteadOf=git@github.com: submodule update --init --depth 1
cmake -S . -B build -G Xcode -DTRACKTION_ROOT="$PWD/build/deps/tracktion-engine" \
  -DCMAKE_OSX_ARCHITECTURES=x86_64 -DCMAKE_OSX_DEPLOYMENT_TARGET=14.0
cmake --build build --config Debug --parallel 4
STUDIO_SYNTH_SCREENSHOTS="$PWD/build/synth-review" ctest --test-dir build -C Debug --output-on-failure
build/Debug/StudioSynthBench --matrix
open build/Studio_artefacts/Debug/Studio.app
```

The matrix covers the six individual engines, four-layer Hybrid, six separate synth tracks, mixed Synth/Sampler, and an offline Hybrid pass. It reports per-block mean and 95th percentile timing, deadline misses, configured voice capacity and sampler PCM bytes. The timing percentages express the fraction of one audio-block deadline; hardware I/O and the DAW graph add separate costs. Build Release for representative benchmarks.

On a physical Intel MacBook, open a copy of a project with a Sampler and ARIA track, add a Synth, and listen to each family's preset. Play and record in one pass with sustain, bend, pressure and CC11. Edit a Hybrid layer and automate Synth Trim, save a preset and the project, then reopen and bounce. Confirm the room send, headphone or interface output, drag-and-drop, and the range of UI sizes. Check Audio Settings and Resource Inspector for underruns and CPU load with several instruments active.

## Remaining compatibility

The recovered Analog source supports up to eight voices, single-voice operation and oscillator pitch offsets. Legato priority, portamento and oscillator glide are pending. Legacy .studiosynth JSON is supported at the patch and preset level. Entire AVAudioEngine project files, the former SwiftUI preset manager, creating MIDI Learn assignments from this editor, and automatic Synth-to-Sampler capture remain separate integration work. The Granular adapter currently accepts mono or stereo source files. Engine response and subjective sound quality remain part of hardware acceptance.

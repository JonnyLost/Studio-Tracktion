# O5 — Live CC1/CC11 conducting

Base: O4 3914660426f1009dc9033b30dedb6898d8934c68. O4 standalone core, Linux Composer and Intel macOS build workflows passed at inspection. Isolated branch; no merge.

## Use
In the Ostinato Engine select a step and set its Density tier, then Apply step. Tier 0 is essential; tiers 1–127 are optional and enter when the global density reaches their threshold. Dots identify optional enabled cells. Existing patterns migrate with all tiers 0, so nothing unexpectedly disappears. The CC1 Intensity and CC11 Density sliders default to 127. Intensity scales new note-on velocities from 25% to 100% of authored values (minimum velocity 1); density changes the set of future note-ons, not the duration of already sounding notes. At 127/127 the original enabled notes and velocities are preserved. Sliders remain usable during finite O4 audition; pattern editing remains locked.

For hardware conducting, turn off MIDI Keyboard Follows Selected Track, release held notes/pedal, remove any track assignment for the chosen enabled physical MIDI input, then select that device and channel in MIDI input. Choose Off for mouse-only control. The device selection and live sliders are session/window state, not permanent global MIDI preferences. Controller data is observed only during audition; the listener does not consume MIDI, create a port or change routing. A routed or unavailable device is refused, and a changed/disconnected route stops audition. Do not route other MIDI inputs to audition destinations or play other notes on those instruments during audition. Only CC1 and CC11 on the selected channel enter the atomic mailbox. Studio does not emit these CC messages to the instrument as part of conducting; the existing MIDI system could still deliver external messages if routing is changed concurrently. No promise of a global MIDI filter. To conduct with Garritan dynamics separately, use another explicitly routed device or later routing controls.

## Engine
Schema 4 adds per-step densityThreshold with backwards readers for schemas 1–3. The precompiled full-density note list contains threshold metadata. Mixed-threshold overlaps at the same physical pitch/channel/track are rejected before normalization, rather than allowing a skipped optional hit to shorten an essential note. Assign separate pitches/channels, shorten gates or equalize thresholds. Same-tier overlapping notes retain O4 normalization. At dispatch the current intensity scales note-on velocity and current density gates admission. Only accepted note-ons enter the owned-note table, so later density changes never leak orphan note-offs or terminate sustained notes early. Stop/stall/context invalidation releases owned notes. The bounded physical listener uses an atomic mailbox and no MIDI-thread UI updates; message-thread audition consumes latest values. No additional instrument instance is created.

Native and standalone CI are enabled for O5; results pending unless separately verified. Physical Oxygen 25 and ARIA behavior still require the user's Mac. O5 remains O4's stopped-transport, message-thread, finite audition, not sample-accurate arrangement playback. CC1 is velocity/intensity rather than sustained orchestral dynamics, CC11 is density rather than expression level. No automation recording or MIDI printing, no per-row controller remapping, no probability/random variations, and no simultaneous keyboard-root following yet.
